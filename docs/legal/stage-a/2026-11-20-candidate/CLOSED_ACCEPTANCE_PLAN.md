### Ручной порядок уведомления при снятии бесплатного курса (D-03)

Оператор фиксирует курс и предполагаемую дату прекращения доступа. Из актуальных
записей Commerce он получает в закрытом контуре список записавшихся с действующими
аккаунтами. Перед отправкой проверяет адресатов и исключает удалённые аккаунты,
удаляет дубликаты. Служебное письмо сообщает, к какому курсу и с какой даты
прекратится доступ, и даёт контакт для вопросов. Маркетинговый выбор не используется.

Запланированная дата должна отстоять от отправки не менее чем на 30 календарных дней.
Оператор сохраняет дату, версию текста, число адресатов и результаты отправки в закрытом
журнале. При существенном сбое отправки оператор сверяет исходы и переносит дату
планового снятия, если соблюдение срока не подтверждено. Исключения обрабатываются
по account_terms §4. Для проверки в canary используется синтетический список и
тестовый транспорт.

## 1. Приёмочные сценарии

Каждый сценарий: команда/действие → ожидаемый результат → артефакт в
`docs/evidence/<дата>-stage-a-closed-acceptance/` (без email, токенов, cookies, IP).

### A-1. Реальный вход по ссылке через /account
1. Гость открывает `/account`, вводит тестовый адрес, проходит SmartCaptcha.
2. Письмо приходит через NotiSend; ссылка открывается один раз; повтор → отказ; через >10 мин → отказ.
3. `GET /v1/me` через прокси Platform: `Cache-Control: no-store`, нет кэширующих заголовков прокси.
4. Cookie сессии: `HttpOnly`, `Secure`, host-only (без `Domain=.flexperiment.ru`).
5. После входа без согласий: запись и плеер недоступны; показана форма согласий
   (ПД и правила — пустые обязательные, реклама — пустая необязательная).
6. Переключатель рекламы на /account (A · #291, `MarketingPreference` → `POST /v1/me/consents/marketing`): read-only SQL — новое действие содержит ровно одно событие `marketing_consent` с текущими release/manifest/document hash, без событий `personal_data`/`account_terms`; аккаунт без собственных обязательных выборов получает `REQUIRED_CHOICES_UNCONFIRMED`; после one-click отписки по ссылке включение переключателя рассылку не возобновляет (G-18).
7. После отметки: в БД событие с точными `release_version`/`manifest_sha256`/`document_sha256`
   (read-only SQL `SELECT kind,granted,document_version,document_sha256 …` по тестовому customer_id).
**Ожидание:** все пункты PASS. Доказательство: HAR без тел/cookies, заголовки, SQL-счётчики.

### A-2. Явная запись и защищённый просмотр (FLEX-128)
1. Гость на странице FREE-курса нажимает «Записаться бесплатно» → вход → возврат к первому доступному уроку; запись создана.
2. Второй пользователь входит, не нажимая кнопку → playback-grant и DRM authorize урока полного FREE-курса отвечают `403 ENROLLMENT_REQUIRED`, записи нет (A · #291).
   Запись — только `POST /v1/me/free-enrollments` с `Origin` витрины COURSES; другой `Origin` или без сессии/согласий → отказ; повтор — идемпотентен.
3. Записанный пользователь: grant выдан, `drmauthtoken` в embed URL, видео декодируется (Chrome/CDM).
4. Негатив: истёкший токен, чужой `vid`, токен другого пользователя в другом профиле — фиксируется известное ограничение ART-36 (bearer), новый license после revocation → отказ.
5. Free-preview урок платного курса: доступен с согласиями без записи; платный урок: нет плеера, нет checkout.
6. Прогресс на старте 0%; статус «Начат»; в `course_access_starts` новой строки нет.
7. На тестовом аккаунте сверить, какие получатели обрабатывают токен DRM с внутренним идентификатором аккаунта, сетевые данные и аналитику просмотра, с применимыми условиями Kinescope (G-06). В отчёте фиксировать только получателей и категории данных. География узлов, обслуживающих только видеофайлы без ПД, сама по себе на результат не влияет.

### A-3. Продолжение просмотра
1. Смотреть ≥60 с, перезагрузить → позиция восстановлена (±5 с).
2. Второй браузер тем же аккаунтом → та же позиция.
3. Старый `clientTs`/`clientSeq` не перезаписывает новую позицию (повтор запроса с меньшим seq → `accepted:false`).
4. В пределах 20 с до конца → старт с 0.

### A-4. Опубликованный каталог
Медиа курса — **решено владельцем (v4.8, 22.11): упрощённый Stage A, вариант S**. Вариант F оставлен только как справка на будущее:
- **вариант S (сокращённый):** статические WebP из FLEX-126 в образе Platform, без S3, worker и DDL. Проверить: изображения отдаются с хоста Platform; в HTML нет ссылок на `*.s3.cloud.ru`; CSP `img-src` не требует S3; карта данных не меняется.
- **вариант F (полный):** медиа через S3/worker (FLEX-63). Проверить дополнительно: публичные URL не раскрывают Kinescope ID; DDL 0041 зарегистрирован и классифицирован; Cloud.ru S3 добавлен в privacy §3 только если туда попадают данные пользователей (ожидается — нет).
1. Публикация курса в Control Room → курс в каталоге, поиске и sitemap на следующем рендере.
2. Unlisted/неопубликованный урок отсутствует во всех трёх.
3. В HTML, RSC payload, search index и sitemap нет Kinescope ID и секретов (`grep` по выгрузке).

### A-5. Платежи выключены
1. `POST` на все платёжные маршруты → `503 PAYMENTS_DISABLED`.
2. Все платные офферы `CLOSED`; на странице платного курса нет ссылки на checkout.
3. Запуск Commerce с `PAYMENT_MODE=mock` в production отклоняется (проверка в тестовой копии конфигурации, не в проде).

### A-6. Точные образы Commerce / Admin / Platform
1. Для каждого из трёх: `/identity` (или `release.json`) → `source_commit` = SHA кандидата.
2. С хоста (read-only, по GO): `docker inspect` контейнера → image digest и label commit; совпадение с Coolify deployment.
3. LAB-образы не входят в эту проверку.
4. Platform собирается **отдельно для каждого окружения** с его `PLATFORM_ORIGIN` (build ARG `Dockerfile.platform`, по умолчанию `https://flexperiment.ru`; F · #290): `/` и `/courses` пререндерятся при сборке, их canonical/og:url берутся из этого значения. Проверка: на canary `canonical` и `og:url` указывают на origin canary, на production — на `https://flexperiment.ru`. Один и тот же digest Platform для canary и production — **FAIL** (canonical canary укажет на production). Значит, для Platform критерий «тот же образ» заменяется на «тот же commit, отдельная сборка на окружение» (G-17).
**Критерий A-6:** CI должен собрать образы для точного SHA кандидата и опубликовать их с неизменяемыми
digest. Развёртывание в каждом окружении использует его утверждённые digest. Независимый read-back с хоста
подтверждает фактически установленные digest, а G-11 сверяет исходный SHA через `/identity`. До доказательства
этой цепочки A-6 остаётся открытым. Сейчас CI собирает образы без публикации, поэтому сохраняется G-12.
Настройка публикации, реестра и развёртывания требует отдельного допуска.

### A-7. Свежее независимое восстановление с подавлением удалений
Ссылка: `docs/release/COMMERCE_V2_BACKUPS.md` §«Independent restore», `COMMERCE_V2_RESTORE_RECONCILIATION.md`.
1. До снимка: тестовый аккаунт B записывается, смотрит, даёт рекламное согласие. Снимок N создан таймером.
2. После снимка: аккаунт B удалён через штатный erasure-owner процесс; аккаунт C отписан от рекламы.
3. Взять объект N из Cloud.ru по `status.json`, сверить размер/SHA-256; расшифровать вне VPS (Mac владельца).
4. `PRAGMA quick_check=ok`, линия `flexperiment-v2`, журнал миграций = кандидат; оба fingerprint схемы в списке допущенных (`pd-retention.ts`, erasure).
5. Применить независимый ledger: B отсутствует во всех таблицах из `DATA_MAP.md` §1 (включая `course_learning_starts`); C не получает рекламу; restore без доступа к ledger отказывает (негатив).
6. Сервис из восстановленной копии не открывается без шага 5.
7. Проверка свежести: `check` возвращает ошибку на устаревшем приватном фикстуре; алерт доставлен.
**Ожидание:** PASS по всем пунктам; удалённая расшифрованная копия уничтожена, сохранены только безопасные выписки.

## 4. Сценарии отказа и действия

| Отказ | Действие |
| --- | --- |
| Хеш опубликованного текста ≠ SHA256SUMS | Не активировать релиз; перепубликовать точные байты |
| `LEGAL_RELEASE_STALE` у пользователей после активации | Ожидаемо (новая редакция); проверить форму повторного согласия |
| Восстановление без ledger открывает сервис | Стоп-фактор; приёмка FAIL, эскалация FLEX-29 |
| `course_learning_starts` вне erasure-списка | FAIL A-7.5; вернуть A (G-01) |
| Identity ≠ кандидат | Не продолжать; классифицировать durable state по DEPLOYMENT_INVARIANTS, без force/rollback по HEAD |
| Платёжный маршрут не 503 | Стоп-фактор; продажи закрыты иерархией, выяснить уровень |
