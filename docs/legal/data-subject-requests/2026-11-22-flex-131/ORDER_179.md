# Подтверждение уничтожения ПД — требования приказа Роскомнадзора № 179

Приказ Роскомнадзора от 28.10.2022 № 179 «Об утверждении Требований к подтверждению уничтожения персональных
данных» (в силу с 01.03.2023). Пересказ по редакции, известной E; перед утверждением сверить с официальным текстом.

## Что является подтверждением

| Способ обработки | Подтверждение |
| --- | --- |
| Без средств автоматизации | Акт об уничтожении ПД |
| С использованием средств автоматизации (наш случай: Commerce SQLite, почтовый журнал) | **Акт об уничтожении ПД + выгрузка из журнала регистрации событий в информационной системе ПД** |

Акт может быть на бумаге (подписи) или электронным (электронная подпись).
**Акт и выгрузка хранятся 3 года** с даты уничтожения.

## Обязательные сведения акта

1. Наименование (ФИО) и адрес оператора — ИП Гурьянов А. А., 650023, г. Кемерово, пр. Московский, 17-360.
2. Наименование (ФИО) и адрес лица, обрабатывавшего ПД по поручению оператора, если уничтожение у него (например, NotiSend).
3. ФИО субъекта(ов) или иная информация, относящаяся к нему, чьи ПД уничтожены — **у нас: email и внутренний идентификатор
   на момент уничтожения**; ФИО не собираем и не добавляем ради акта.
4. ФИО, должности лиц, уничтоживших ПД, и их подписи.
5. Перечень категорий уничтоженных ПД (по DATA_MAP Stage A: аккаунт, сессии, согласия, записи на курсы, даты начала,
   позиции просмотра, записи доступа к видео, маркетинговые данные, журнал писем).
6. Наименование уничтоженного материального носителя и число листов — только для неавтоматизированной обработки.
7. Наименование информационной системы, из которой уничтожены ПД (у нас: «Flexperiment Commerce V2», при необходимости
   отдельно — журнал NotiSend).
8. Способ уничтожения (у нас: удаление записей SQLite с `secure_delete=ON` штатной процедурой erasure; для
   резервных копий — применение независимого ledger при восстановлении и уничтожение копии по сроку).
9. Причина уничтожения (тип обращения по матрице: отзыв согласия, удаление аккаунта, ч. 3 ст. 20 и т. п.).
10. Дата уничтожения.

## Обязательные сведения выгрузки из журнала

- ФИО субъекта или иная информация, относящаяся к нему (email/идентификатор);
- перечень категорий уничтоженных ПД;
- наименование информационной системы;
- причина уничтожения;
- дата уничтожения.

Если журнал не содержит части сведений, **недостающие указываются в акте**.

## Разрыв для Commerce (передать через координатора, FLEX-131 код)

Журнал erasure и независимый ledger хранят хеши субъекта и счётчики, но выгрузка в форме, покрывающей поля выше
(категории, причина, дата, система), пока не формируется. Нужна read-only команда owner CLI «выгрузка для акта»
по номеру обращения: без хранения email в открытом виде дольше, чем требуется для акта (акт — закрытый документ
владельца, не Git/Plane). До неё — недостающие поля вносятся в акт вручную по плану из регламента.
