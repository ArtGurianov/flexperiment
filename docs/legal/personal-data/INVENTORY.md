## Варианты выдачи на следующем этапе

На этой ревизии Commerce V2 запускает фоновые циклы в собственном процессе, при доступном fence через
`run("WORKER", ...)`. `AfterResponseTasks` отслеживает обещания до завершения процесса, но сам по себе не
сохраняет очередь после сбоя. Циклы native расчётов и кампаний зависят от включения соответствующих режимов.
Для фоновой выдачи потребуется собственная долговечная заявка или подтверждённый общий диспетчер в том же
процессе. Сборщик и проверки результата следует проектировать отдельно от способа доставки. Условия выбора
и сценарии приведены в [ADR](../../architecture/personal-data-lifecycle.md#самостоятельная-выдача-в-my).

## Воспроизведение

```sh
pnpm install --frozen-lockfile
pnpm commerce-v2:check-migrations
pnpm data-registry:generate
pnpm exec vitest run commerce-v2/test/personal-data-registry.test.ts
git diff --exit-code -- docs/legal/personal-data/REGISTRY.md
```

Тест покрытия использует штатный миграционный раннер. Отдельные синтетические проверки добавляют
неклассифицированную и убирают существующую колонку в памяти, проверяют дубликаты и ссылки, отсутствие
цели у ПД, запрещённую прямую выдачу и соответствие Markdown исходному YAML. Автоматическая сверка SQLite
не подтверждает содержимое JSON, внешних систем, журналов и рабочего хоста. Эта поставка даёт основание
для ревью и последующих квалификаций. Эксплуатационная, юридическая и провайдерская приёмки остаются отдельными.
